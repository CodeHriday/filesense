# Filesense - Feature triage (Phase 4)

How to read this table:
- One row per user-facing feature (plus a few platform capabilities that need a decision). Features that several areas implement are merged into one row; the Areas column lists every contributing area.
- Recommendation is the synthesizer's proposal. Decision records the outcome: the user accepted every recommendation (relayed by the coordinator). For the 9 rows recommended "ask", the synthesizer chose keep, change or drop, and the user accepted that choice; those rows say "decided on recommendation, user accepted".
- Evidence cites the area note flag (for example `AUTH SEC-1`) and, where it matters, the code line. For the 12 done-with-issues areas (PROC, PROF, DQ, VAS, SLA, ETL, SCHD, EML, AI, SEC, WEB, MIGV) the `<AREA>.verify.md` file overrides the note.
- Corrections applied over passed notes (details in cross-cutting.md, section 0): VND BUG 13 is wrong for prod; the AUD/ADM "audit failure after COMMIT gives ROLLBACK + 500" claim is wrong (it is silent); CONN create stores secrets in plaintext; prod `storage_connections` has PK `connection_id` and no `id`/`provider_type`/`is_active`; FDV is right and AI.md :97-98/:123 is wrong about the AI payload; prod `user_groups.group_id` references `access_groups(id)`.
- Any "delete fails because no ON DELETE" claim that rests only on `database_ddl_*` dumps is unsupported (those dumps never print ON DELETE or CHECK).
- Cross-cutting findings (X1-X9, C1-C10) and decisions (D1-D12, resolved in section 7) are defined in cross-cutting.md.
