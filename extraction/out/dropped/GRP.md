# GRP - Dropped features

- F13 Legacy groups API: the four handlers shadowed at the same path, the reachable "my groups" listing, bulk add-users-by-list, and remove-user with the Default Group refusal (403). Reason: triage decision drop, D4. Superseded by access groups; the reachable handlers validate ids against the retired legacy groups table but write the access-group membership store, so they act on mismatched ids. The frontend helpers that call them (get user groups, add user to group, remove user from group, get group users) go too.
- F13 Startup default-group backfill (enrolled every user with no membership into an access group named "Default Group"). Reason: it sits in the dropped legacy block, and no code creates that access group. Whether new users should auto-join a default group is an open question in REQ-GRP-007.
- F14 IAM-style policy engine: policy CRUD, user and group policy attachments, policy evaluation and its evaluation cache, the per-user policy listing, the seed policies (AdministratorAccess, ReadOnlyAccess), the second project policy engine and the two unused policy authorisation middlewares. Reason: triage decision drop, D4. Nothing enforces these policies, group attachments never applied (they read a membership store nothing writes), and no UI calls the engine.
- F14 ABAC attributes (user attributes, resource attributes, attribute definitions) and SCIM provisioning tables (configurations, sync logs, resource mappings). Reason: triage decision drop. Nothing writes them, and nothing reads the definitions or SCIM tables.
- F14 Second membership store (the separate group-member table that the policy engines and some other areas read). Reason: D4 makes one membership store the only one. Readers in other areas must switch (REQ-GRP-011).
- F80 Groups screen presented as a container for business processes ("Create and manage groups to organize your business processes"), with its group-processes link. Reason: triage decision drop (business processes retired, D6). The screen also sent no credentials and always failed. Access groups are managed on the access group screen (REQ-GRP-013).
