# EML - Email providers & domains

## Summary
Two route files plus services. Email provider connections are stored in the shared `storage_connections` table (emailConnectionRoutes.js:18-31) with type in smtp, gmail_oauth2, outlook_oauth2, sendgrid, ses, azure_email, gcp_email (:30). They are "application-wide" (project_id null, :141) except OAuth2-created ones, which take a project_id (:713, :958). Allowed email domains are a separate table `allowed_email_domains`, enforced when sending (NotificationService.js:254-277).
Mounts (server.js:13930-13941): `/api/email-connections` = authenticateToken only (no admin check); `/api/allowed-email-domains` = authenticateToken + requireAdmin. Adapters are chosen by EmailProviderFactory.js:25-51.
The nonce OAuth flow (entries 8-11) is broken: it requires `../utils/cache` (emailConnectionRoutes.js:515, :595, :651, :756), which does not exist (no file under backend/utils/cache*; `getCacheClient` is defined nowhere in backend). The frontend uses only that flow (EmailProvidersConfig.jsx:270), so in-app Gmail/Outlook authorization does not work.
ConnectionService.createConnection stores `JSON.stringify(config)` without encryption (ConnectionService.js:707), so secrets and tokens of connections created through this area are plaintext (see Flags).
Not deeply traced: the individual adapters' send logic (only the facts cited below), the SMTP and SendGrid adapters, and the frontend pages beyond the API call sites.

## Entry points

### Email connections (all behind authenticateToken, server.js:13931)
1. GET /api/email-connections/ (emailConnectionRoutes.js:14). Any authenticated user. Returns every storage_connections row of an email type, newest first, with columns connection_id, type as provider_type, name, status, timestamps, project_id, description, config (:19-32). Response `{success, connections}`. 500 on error. No project filter, no masking of config here (raw column read, :28). No filter on the prod soft-delete columns (see Flags).
2. GET /:connectionId (:51). Any authenticated user. Calls ConnectionService.getConnectionById, which is `SELECT *` (ConnectionService.js:624) and throws when no row exists (:628-629, wrapped as "Failed to fetch connection" :635), so the route's 404 (:57) is unreachable: a missing id (or a malformed UUID) gives 500. 400 "not an email provider" if type not in the list (:66). Returns `{success, connection}` including raw config.
3. POST / (:91). Any authenticated user (no role check). Inputs name, provider_type (or legacy `type`, :102), description, config. 400 if name, type or config missing (:105-133); 400 if type not in the list (:121). Calls ConnectionService.createConnection with project_id null, connection_direction 'outbound', status 'active' (:137-145). The service ignores the caller's status and hardcodes 'active' (ConnectionService.js:708), stores config as `JSON.stringify(config)` with no encryption (:707), and rejects a case-insensitive duplicate name (:671-678, thrown, so 500 via the wrap at :725). The service returns only connection_id, name, type, status, connection_user, connection_direction, description, authentication_method, path, created_at, updated_at (:701-702), so the 201 `{success, connection}` has no config and no project_id. No config validation against the adapter's validateConfig.
4. PUT /:connectionId (:168). Any authenticated user. The route reads name, description, config, status (:180-183); 400 if none (:185). The service reads `is_active`, not `status` (ConnectionService.js:758, :840-843), so `status` is silently dropped. A PUT with only `status` leaves only `updated_at` in the field list and returns the existing row (:854-856), reported as success. That early return skips COMMIT and ROLLBACK, so the client is released (finally :873-875) while the transaction opened at :742 is still open. A missing id throws (:750-751) so the route's 404 is unreachable (500). Config updates encrypt newly supplied sensitive fields (:827-834, by-type list :787-804) and merge with the stored config, so a stored config can mix plaintext (from create) and ciphertext (from update). Empty sensitive values are not overwritten (:814-819). No duplicate-name check on update. Response is `RETURNING *` (:859), so it includes config. No check that the connection is an email type (see Flags).
5. DELETE /:connectionId (:225). Any authenticated user. A missing id throws (ConnectionService.js:891-893), so the route's 404 is unreachable (500). On success the service returns `true` (:896), so the response is `{success, deleted: true}`. No email-type check; no check for usage by alerts, digests or workflows. It is a hard `DELETE FROM storage_connections WHERE connection_id = $1` (ConnectionService.js:886-889); the consequences on prod are in Flags.
6. POST /:connectionId/test (:261). Any authenticated user. Requires `to_email` (400, :266). The 404 (:275) is unreachable for the same reason as entry 2. Parses config, decrypts via notificationService.connectionService.decryptSensitiveFields (:293), sends a fixed message "Test Email from Data File Observatory" through NotificationService.sendWithProvider (:307). The provider object uses `connection.connection_id` as its id (:300), and the route does not go through getEmailProvider. Because create stores plaintext, decryptSensitiveFields throws for a plaintext secret ("Failed to decrypt data - key may have changed" / format error for a value without ':', encryption.js:72-120), so the test returns 500 for connections created through POST / that hold a secret; the substring mapping below may rewrite the message. Side effect on success: a real email is sent, and the allowed-domain check applies (a blocked recipient gives success false). Failure returns 500 with `error` and `details`. Thrown errors are mapped by substring to friendly messages: invalid/expired/revoked/401 gives "API key is invalid..." (:353); rate limit/429 (:355); ECONNREFUSED/ENOTFOUND (:357); authentication/unauthorized (:359). No email-type check.
7. POST /oauth2/authorize-url (:382). Any authenticated user. No authorizeProjectResource and no email-type check, so any user can mint a state for any project_id. Inputs provider (gmail|outlook), redirect_uri, project_id, all required (400). State is base64 of JSON `{project_id, timestamp}` (:412), not stored or signed server-side. Builds the Google URL (scope gmail.send, access_type=offline, prompt=consent, :428-435) or the Microsoft URL (scope `Mail.Send offline_access`, tenant `common`, :446-451). 500 if the client ID env var is missing. Returns `{auth_url, state}`. The redirect_uri is caller-supplied.
8. POST /oauth2/gmail/auth (:477). Uses authorizeProjectResource with permission 'connection:create' on body.project_id (:478-482). Requires project_id and req.user.id (400/401). Generates a 32-byte random hex nonce (:512), then `require('../utils/cache')` at :515 fails because the module does not exist, so inside the try this always ends in 500 "Failed to initiate OAuth2 flow". The code after it (caching `oauth2_state:<nonce>` for 600 seconds, :512-525; redirect URI `${API_BASE_URL || 'http://localhost:3000'}/api/email-connections/oauth2/gmail/callback`, :527; response `{auth_url, nonce}`) is therefore never reached.
9. POST /oauth2/outlook/auth (:557). Same as 8 for Outlook (:582-622); the failing require is at :595. Always 500.
10. GET /oauth2/gmail/callback (:636). Registered under the JWT mount; the comment says Google redirects without Authorization headers (:634). Reads code, state(nonce), error. Every outcome is a redirect to `/oauth2-callback?success=...`. Because the cache module require fails (:651), the callback redirects with an error; no nonce can exist anyway since the auth endpoint never stores one. Intended logic, not reachable: provider error; missing code/nonce; cached state missing; JSON parse; provider must be 'gmail' (:673); age > 600000 ms (:680), in which case the key is deleted (:682); then deletes the state (one-time, :687). Exchanges the code at https://oauth2.googleapis.com/token (:695) (JSON body). Creates a connection named 'Gmail OAuth2 Connection', type gmail_oauth2, project_id from state, config {access_token, refresh_token, expires_at = now + expires_in*1000} (:709-721). The user_id in the state is only logged, not used for authorization.
11. GET /oauth2/outlook/callback (:741). Same as 10, with the failing require at :756, the token endpoint https://login.microsoftonline.com/common/oauth2/v2.0/token (:800) (request sent as JSON, not form-encoded) and name 'Outlook OAuth2 Connection'.
12. POST /oauth2/callback (:844). authorizeProjectResource 'connection:create', project taken from the base64 state (:848-864). Used by the SPA per inventory (the frontend call site in this area, EmailProvidersConfig.jsx:270, calls the nonce flow instead). Requires provider, code, state (400). Decodes the state, rejects it if older than 600000 ms (:898), 403 if req.projectId differs from the state project (:906). Exchanges the code for gmail or outlook (redirect_uri from body), else 400 'Invalid provider'. Creates a connection named `name` or "Gmail/Outlook OAuth2 Connection" with project_id from the state; the duplicate-name check (ConnectionService.js:671-678) fails the second creation with the default name (500). Returns `{success, connection}` (create's reduced column list). 500 includes `details: error.response?.data || error.message` (:984).

### Allowed email domains (authenticateToken + requireAdmin, server.js:13941)
13. GET /api/allowed-email-domains/ (allowedEmailDomainsRoutes.js:6). Lists id, domain, description, is_active, created_by and timestamps, ordered by domain.
14. POST / (:27). Requires domain (400). Normalised with lower-case and trim; a non-string body value makes `domain.toLowerCase()` throw (500). Regex `^[a-z0-9][a-z0-9.-]*\.[a-z]{2,}$` (:41), else 400. INSERT with created_by = req.user?.id. 201 on success; 409 on unique violation 23505 (:64).
15. PUT /:id (:79). Optional domain (same regex), description, is_active. 400 if no fields; sets updated_at = NOW(); 404 if no row; 409 on a duplicate. No type check on is_active. `:id` is not validated as an integer, so a non-numeric id gives 500 from Postgres.
16. DELETE /:id (:163). Hard delete; 404 if no row; returns `{deleted:{id,domain}}`. A non-numeric `:id` gives 500 from Postgres.
17. POST /validate (:199). Body `{emails: []}` (400 if not an array). Reads active domains. If none are active, returns `valid:true` with 'No domain restrictions configured' (:216). Otherwise exact domain match (no subdomain matching); returns `{valid, invalidEmails, allowedDomains}`. A non-string entry in `emails` throws at `email.split` (500).

### Frontend routes
- /email-providers (src/pages/EmailProvidersConfig.jsx; App.jsx:452, wrapped in ProtectedRoute, no role check). Calls the domain CRUD (:62, :76, :102, :113) and `/api/email-connections/oauth2/${provider}/auth` (:270), which always fails with 500 (entries 8-9).
- /oauth2-callback (src/pages/OAuth2Callback.jsx, App.jsx:453). Not wrapped in a protected route per inventory.

### Non-HTTP behaviour
- Send-time domain enforcement: NotificationService.sendWithProvider (NotificationService.js:254-277) validates all recipients via EmailDomainValidationService.validateEmails and returns `{success:false, domainValidationFailed:true}` without sending. EmailDomainValidationService (:1-108): active-domain cache TTL 5 * 60 * 1000 ms (:8), held per process in memory (:6-8); no active domains means everything allowed (:46); an email without exactly one '@' is invalid when restrictions exist (:35, :60); on DB error getAllowedDomains returns [] (:27), which means all domains are allowed.
- Provider loading for real sends: NotificationService.getProviderChain (:72-112) reads the policy's provider ids and loads each through getEmailProvider (:102-104), which queries `SELECT id, type, config, name, description FROM storage_connections WHERE id = $1 AND is_active = true` (:35-40) and then decrypts (:49-52). This is the only provider loader used for real sends in this file.
- Adapter factory (EmailProviderFactory.js:25-51): unknown type throws; it passes only `config` to each adapter constructor (:34 for SES). getAvailableProviders lists 7 types; the comments mark gmail/outlook as "Coming soon" (:64-65), although the adapters exist.
- Adapter facts: Gmail token refresh when within a 5 minute buffer of expiry (GmailOAuth2Adapter.js:129); the adapter keeps refreshed tokens in memory and returns updatedCredentials for NotificationService to persist (NotificationService.js:287-293). GmailOAuth2Adapter reads config.client_id, client_secret and from_email (:36-40) and validateConfig requires them (:357-366); connections created by the OAuth flows store only access_token, refresh_token and expires_at, so they lack these and cannot refresh or send as stored. AWS SES assumed-role cache TTL 45 * 60 * 1000 (AwsSesAdapter.js:15). Because the factory passes no second argument, `authConfig` is `{}` (AwsSesAdapter.js:18-21); the AssumeRole branch needs `authConfig.role_arn` (:46, :60-63), which is never set, so SES uses the default AWS credential chain and never assumes a role (the header's claim of IAM role support, :6, is not reachable through the factory). `authentication_method` defaults to key-based (:22). SES validateConfig requires access_key_id, secret_access_key and region (:313-319), so IAM-role configs would fail validation if it were called. Azure requires connection_string or endpoint, an access key (`!this.accessKey`, AzureEmailAdapter.js:247-249) and from_email (:244-250). GCP requires password or private_key, and username or service_account_email (:149-152), default `smtp_port` 587 (GcpEmailAdapter.js:30). Config validation (validateConfig) is not called by the create or update routes.

## Data touched
- storage_connections (read/insert/update/delete via pool and ConnectionService); filtered on type IN the 7 email types for the list only. Prod has a unique index on lower(name) (FileSence_prod_schema_Jan_05_1767780691950.sql:6130, idx_connections_name_unique_lower).
- Prod storage_connections columns (FileSence_prod_schema_Jan_05_1767780691950.sql:6108-6128): PK `connection_id varchar(255)`, type, name, config, status, connection_direction, project_id, connection_user, description, authentication_method, auth_config, path, and soft-delete columns is_deleted, deleted_at, deleted_by (:6123-6125). There is no `id` and no `is_active` column.
- allowed_email_domains (id, domain, description, is_active, created_by, created_at, updated_at).
- Intended cache key `oauth2_state:<nonce>` (600 s): never written, the cache module does not exist (see Summary).
- Env: GMAIL_CLIENT_ID, GMAIL_CLIENT_SECRET, OUTLOOK_CLIENT_ID, OUTLOOK_CLIENT_SECRET, API_BASE_URL (names only).
- External: accounts.google.com, oauth2.googleapis.com, login.microsoftonline.com, plus the provider send APIs.

## Flags
- BUG: The nonce OAuth flow requires `../utils/cache` (emailConnectionRoutes.js:515, :595, :651, :756), which does not exist; `getCacheClient` is defined nowhere. POST /oauth2/gmail/auth and /oauth2/outlook/auth always return 500, the GET callbacks redirect with an error, and EmailProvidersConfig.jsx:270 uses only this flow, so Gmail/Outlook authorization in the app is dead.
- SECURITY: ConnectionService.createConnection stores `JSON.stringify(config)` unencrypted (ConnectionService.js:707), so SMTP passwords, API keys, cloud keys and OAuth tokens created via POST / and the OAuth flows are plaintext. updateConnection does encrypt new sensitive fields (:827-834), so rows can be mixed. GET /:id (`SELECT *`, ConnectionService.js:624) and GET / (emailConnectionRoutes.js:28, :73) return the raw config to any authenticated user (plaintext for create-made rows, ciphertext for updated fields).
- BUG: Real sends cannot load a provider on prod. NotificationService.getEmailProvider runs `SELECT id, ... FROM storage_connections WHERE id = $1 AND is_active = true` (NotificationService.js:35-40), and the prod table has neither `id` nor `is_active` (PK is `connection_id`, FileSence_prod_schema_Jan_05_1767780691950.sql:6108-6128). The query therefore fails with a Postgres "column does not exist" error before any decryption is attempted, and the error is logged and rethrown (:58-64). getEmailProvider is the only provider loader for real sends (called from getProviderChain, :102-104). Where the query does succeed (for example on a dev database that has those columns; not checked), `decryptSensitiveFields` at :49 throws for plaintext secrets, so real sends fail for connections created through POST /.
- BUG: Plaintext secrets break decryption in the test route: it calls decryptSensitiveFields (emailConnectionRoutes.js:293), which throws on plaintext values, so test sends return 500 for connections created through POST / that hold a secret. The test route does not use getEmailProvider and uses `connection_id` as the provider id (:300), so it does not hit the `id`/`is_active` query failure above.
- BUG: ConnectionService.updateConnection builds `is_active = $n` when `is_active` is passed (ConnectionService.js:840-843), a column that does not exist on prod (FileSence_prod_schema_Jan_05_1767780691950.sql:6108-6128), so such an update fails on prod. EML's routes do not reach it, because they pass `status`, which the service ignores. The test route and NotificationService.persistCredentials pass only `config` (NotificationService.js:226-228), which does not touch `is_active`.
- BUG: Prod soft-delete columns are ignored. storage_connections has is_deleted, deleted_at and deleted_by (dump :6123-6125), but EML's list (emailConnectionRoutes.js:19-32), GET (ConnectionService.js:624) and PUT (ConnectionService.js:859) do not filter or set them, and DELETE is a hard delete (ConnectionService.js:886-889). On prod the hard delete nulls the connection links on alert_policies.email_connection_id and alert_runs.email_connection_id (ON DELETE SET NULL, dump :7322, :7334) and on vendor_agreements (ON DELETE SET NULL per the verifier, dump :7891; that line was not re-read here). Where vendor_file_profiling_results.connection_id references the connection, the FK has no ON DELETE action (dump :7897), so the delete fails and the route returns 500. Deleting a connection therefore silently removes an alert policy's email connection.
- UNCLEAR (cross-reference to ALRT): NotificationService.getProviderChain selects `ap.provider_connection_id` (NotificationService.js:78) and `ap.failover_connection_id` (:79), while the prod FK on alert_policies is named `email_connection_id` (dump :7322). Whether `provider_connection_id` exists on alert_policies is for ALRT to confirm.
- SECURITY: Email connection create/update/delete/test and list have no role check, only authenticateToken (server.js:13931; routes :14-261). Any logged-in user can create, change or delete the application-wide providers. The only role gate is requireAdmin on the domain routes (server.js:13941), so the policy is inconsistent.
- SECURITY: PUT and DELETE /:connectionId and POST /:connectionId/test do not check the connection type, so they act on any storage_connections id (:193, :229, :273); GET /:id does check (:66). None of getConnectionById, PUT or DELETE scope by project, so project-tied OAuth connections are editable by anyone.
- SECURITY: POST /oauth2/authorize-url has no project permission check and no email-type check (:382), so any user can mint a state for any project_id.
- SECURITY: POST /oauth2/authorize-url and POST /oauth2/callback use an unsigned base64 state that the client can forge. The callback's project check relies on the same state (:848-864, :906), and it has the 'connection:create' permission check for that state's project; no nonce or user binding. Redirect_uri is taken from the request body (:384, :868).
- SECURITY: The GET OAuth callbacks (:636, :741) sit behind authenticateToken at the mount while their own comment says no Authorization header arrives. Whether they could work depends on authenticateToken (not traced); in any case they currently fail at the missing cache module. Intended logic would create the connection using the project_id in cached state with no permission re-check and without verifying the callback user is the user who started the flow.
- SECURITY: Error details from the token exchange are returned to the client (:984) and redirected in the URL (:733).
- DUPLICATE: Two OAuth2 flows for the same result: authorize-url + POST callback (base64 state, :382/:844) versus nonce flow + GET callbacks (:477-840). Gmail and Outlook GET callbacks and auth endpoints are near copies (differences: provider strings, endpoints, env names, connection names). The frontend at EmailProvidersConfig.jsx:270 calls only the nonce flow, which is broken.
- DUPLICATE: Allowed-domain checking exists in two places: the route /validate (allowedEmailDomainsRoutes.js:199-249) and EmailDomainValidationService (:39-85). They differ: the route has no cache, treats a missing domain as 'unknown', and allows multiple '@' (split()[1]); the service caches for 5 minutes, requires exactly one '@' and returns different message text. The domain regex is repeated in POST and PUT (:41, :90). The email type list is repeated 3 times in the routes (:30, :65, :120) and again in EmailProviderFactory.js:59-65.
- DUPLICATE: Test-send logic (parse, decrypt, build provider) is mirrored in DigestService.js:23 (comment) and visualWorkflowExecutor.js:746.
- BUG: Unreachable 404 branches: the service throws on a missing row, so GET /:id, PUT, DELETE and test return 500 instead of 404 (ConnectionService.js:628, :751, :892; emailConnectionRoutes.js:57, :275).
- BUG: PUT `status` is ignored because the service reads `is_active` (ConnectionService.js:758, :840). A status-only PUT returns early without COMMIT/ROLLBACK, so the client is released inside an open transaction (:855, :873-875).
- BUG: createConnection ignores the passed status and hardcodes 'active' (ConnectionService.js:708).
- BUG: OAuth-created connections store no client_id, client_secret or from_email (emailConnectionRoutes.js:709-721), which GmailOAuth2Adapter requires (:36-40, :357-366), so they cannot send as stored.
- BUG: The case-insensitive duplicate-name check (ConnectionService.js:671-678) makes a second OAuth connection with the fixed names 'Gmail OAuth2 Connection' / 'Outlook OAuth2 Connection' (or the default name in POST /oauth2/callback) fail with 500. Prod also has a unique index on lower(name) (FileSence_prod_schema_Jan_05_1767780691950.sql:6130).
- BUG: The SES factory passes only config (EmailProviderFactory.js:34), so authConfig is {} and the aws-iam-role branch never assumes a role (AwsSesAdapter.js:18-21, :46); the CONN role_arn/iam_role_arn mismatch is therefore never reached from this area.
- BUG: POST / logs `type` (:149), which is undefined when the client sends `provider_type`; the effective value is connectionType.
- BUG: Domain cache is never cleared by the CRUD routes (the grep found no clearCache caller in the area; EmailDomainValidationService.js:102 defines it), so changes can take up to 5 minutes to affect sending, while /validate reflects them immediately. The cache is per process and in memory (:6-8), so each instance lags independently.
- BUG: DB failure while loading allowed domains returns [] = "no restrictions" (EmailDomainValidationService.js:25-28), so enforcement fails open.
- BUG: Wrong status code on test failure: send failures return 500 (:336) even for client-side config problems; the substring matching maps any message containing "invalid" to an "API key" message (:353) regardless of provider.
- BUG: Create's status is ignored (hardcoded) and update's `status` is dropped (see above); domain PUT passes is_active unvalidated.
- BUG: Non-numeric `:id` on domain PUT/DELETE gives 500 from Postgres; non-string `domain` (POST) or non-string `emails` entries (/validate) throw and give 500.
- UNCLEAR: Microsoft token exchange is sent as JSON (:800), and no refresh token is stored unless offline_access is granted; not traceable further because the flow is unreachable.
- UNCLEAR: getAvailableProviders comments "Coming soon" for gmail/outlook (EmailProviderFactory.js:64-65) although adapters exist.
- UNCLEAR: Email list includes OAuth connections with a non-null project_id (:26), so "application-wide" is not strictly true; the list ignores project membership.
- DEAD: EmailProviderFactory.validateProviderConfig, testProviderConnection, getProviderDisplayName and getAvailableProviders: no callers found in the routes in this area (only definitions, EmailProviderFactory.js:57-123). Not exhaustively grepped across the repo.
- DEAD: The nonce-flow bodies after the failing require (caching, state check, token exchange and connection creation in entries 8-11) cannot run while `../utils/cache` is missing.

## Domain terms
- Email connection / email provider / provider / storage connection (same table row; `provider_type` in the API = `type` in the DB; `type` accepted for backward compatibility, :101).
- Provider types: smtp, sendgrid, ses (AWS SES), azure_email (Azure Communication Services), gcp_email (GCP SMTP Relay), gmail_oauth2, outlook_oauth2.
- Allowed email domain / domain restriction (empty active list = unrestricted).
- OAuth2 state / nonce (two schemes); connection_direction 'outbound'.
- Test email (to_email).
