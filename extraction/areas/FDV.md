# FDV - File detail, profile and quality views (UI)

Scope note: DataProfile.jsx is 4,504 lines. Traced: the load/poll path, quality-rule run/save/revalidate, governance permission logic, header and page banners, tab bar, column-quality heuristics, and the render bodies of the Overview, Columns, Preview, Quality Rules and Schema Builder tabs. Child components read: FilePreview.jsx (whole) and AIDQSuggestionsTab.jsx (lines 1-420 plus a grep of the rest; the JSX below :420 was not read). Not traced: SchemaHistoryTab internals (only its API call), QualityTooltip, the modal components. Backend behaviour is not described here; only what the UI calls.

## Summary
Three React routes, all wrapped in `ProtectedRoute` (login required only). `/profile/:fileId` is a large tabbed page (attributes, profile, schema history, preview, DQ suggestions, quality rules, schema builder) that loads one batch payload, polls while the file is processing, and edits governance (ownership, sensitivity, tags, policies) and quality-rule assignments. `/quality/:fileId` shows a stored quality score and per-column completeness, with a "Run Quality Check" button gated by `hasWritePermission('quality')`. `/report/:fileId` runs a quality check with one hard-coded completeness rule and shows/exports the result. There are three separate quality notions on screen: server score (QualityChecks), quality-check report (QualityReport), and client-computed column issues plus rule violations (DataProfile).

  - Severity level: danger > warning > info > none (:198-200).
  - Semantic type is inferred from column NAME regexes then data type (:48-105), e.g. `/phone|tel|mobile|fax|cell/` (:53), `/ssn|...|tin|ein|itin/` (:79), `/\burl\b|website|link|href/` (:99). - Min/max shown only for numeric types list (:1086) or type containing "datetime" (:1091); integer types rounded and `toLocaleString`, others `formatDecimal(value,2)` (:1112-1119). Masking: `_accessLevel||accessLevel` in masked/denied/none (:1129).

### 10. Schema Builder tab (within /profile/:fileId)
- Trigger: tab `schema-builder`, rendered only when `!isVendorUser` (:4308) via `renderSchemaBuilderTab` (:3678-3922). Rules data loads lazily on tab activation (:1888-1894).
- Who: any non-vendor logged-in user. No permission check on toggles or the download.
- Views: empty state "No column data available" when the profile has no columns (:3679-3687); spinner while `schemaBuilderLoading` (:3689-3695).
- Column table (:3729-3808): per column shows Name, mapped schema type, Nullable (Yes/No), PII, and one toggle button per `availableGenericRules` (:3775-3798). PII = `col.pii` or any column governance tag whose `tag_name` lowercased contains 'pii' (:3750). The generated JSON uses only `pii: col.pii || false` (:1811); see BUG 20.
- `mapProfileTypeToSchemaType` (:1792-1801), on the lowercased profile type (default 'string'): contains 'int' -> `int`; contains float/decimal/number -> `float`; 'boolean' or 'bool' -> `boolean`; contains both date and time -> `timestamp`; contains date -> `date`; contains time -> `timestamp`; else `string`. The order matters: any type containing 'int' (e.g. "interval", "point") maps to `int`.
- Nullable: `col.missing > 0 || col.nullable !== false` (:1810, :3748). Because `col.nullable` is only false when explicitly false, nearly all columns come out nullable (see BUG 16).
- String width: for schema type `string` with `col.max_length`, `width = Math.min(Math.ceil(col.max_length * 1.2), 255)` (:1814-1816).
- Column rule toggle: `handleColumnRuleToggle` (:1710-1780) lowercases the column name as key, updates `columnDQAssignments`, `ruleColumnAssignments` (inverse map, case-insensitive duplicate guard) and `selectedRuleIds` (a rule is deselected only when no column keeps it, :1742-1749), applies the state optimistically, then auto-saves via the save coordinator debounced 400 ms (:1764-1779). Save errors are only logged to the console (:1777). So the Schema Builder saves automatically, unlike the Quality Rules tab, which needs "Save Rules". Both write the same assignments.
- File-level rules (:3810-3852): buttons for each `availableFileLevelRules` entry, labelled "Record Count" for `record_count`. Selections live in `fileLevelDQSelections` (:1782-1790) which is component state only: it is never sent to the server and only affects the generated JSON (:1833-1849). The selections are lost on reload. Empty state tells the user to add a `record_count` rule in the Quality Rules tab (:3819-3822).
- `generateSchemaJSON` (:1803-1852): returns null without profile columns; output `{columns:[{name,type,nullable,pii,[width],[quality_rules]}], [file_quality_rules]}`. `quality_rules` is the list of `rule_type` strings for the column's assigned rule ids (:1820-1826). `file_quality_rules` entries are `{rule_type, config}`, where `config` is `rule_config` (parsed from string if needed, `{}` on parse error) and is omitted when empty (:1833-1849).
- Download ("Generate Schema" button, :3718-3725): `handleDownloadSchema` (:1854-1871) writes pretty-printed JSON (2-space indent) via a Blob; error 'No schema data available' if null. Filename `${name without extension}_schema.json` where `name = file?.original_name || file?.file_name || 'file'` (:1865-1866). The header uses `file.filename` (:3973), and grep finds no other use of `original_name` or `file_name` in DataProfile.jsx, so the download is likely always `file_schema.json` (see BUG 15; depends on whether the API also returns those fields, not visible here).
- Preview and copy (:3854-3919): the Schema Preview `<pre>` shows the pretty-printed JSON (max height 300). The Copy button writes minified JSON (`JSON.stringify(generateSchemaJSON())`, :3862) so it pastes into Excel on one line; "Copied!" feedback lasts 2000 ms (:3865). The clipboard promise has no `.catch`, so a clipboard failure is silent/unhandled.
