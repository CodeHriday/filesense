A — Most likely root causes (based on your code & styles)

Layout ran while canvas/container size was zero or not yet measured.

If loadGraph() or getLayoutedElements() executes while the canvas is hidden or has clientWidth === 0, dagre computes positions using default values and nodes land at/near 0,0. (Your app uses a “Show/Hide Filters” panel and you call fitView() in a setTimeout; if the DOM is not fully laid out the layout will be wrong). See LineagePage.jsx.

Dagre node size ≠ rendered node size → incorrect overlap math.

You use nodeWidth = 280 and nodeHeight = 120 in getLayoutedElements() but your CSS sets .lineage-node min-width:150px max-width:250px and internal content can change height. Mismatch causes computed positions to overlap. See LineagePage.css.

Missing or incorrect edges passed to dagre (or edges are empty).

Dagre positions nodes based on connectivity; if edges array is empty, nodes may all be placed at the default or in one column. Verify flowEdges actually contains correct source/target ids. See transform of backend edges in LineagePage.jsx.

Nodes not uniquely identified (duplicate IDs) or non-string IDs.

Duplicate node ids or numeric ids can break the graphlib map lookups and cause unexpected positions. Ensure id is unique string per node. (You map response.nodes.map(node => ({ id: node.id, ... })) — verify node.id uniqueness in backend). See fetch/transform.

Calling useReactFlow() and reactFlowInstance.fitView() before the ReactFlow instance is ready.

You call reactFlowInstance.fitView() in a setTimeout after setNodes, but reactFlowInstance can be undefined if React Flow hasn’t mounted. This won’t directly stack nodes but can hide scale/translation behavior that makes it look collapsed. See LineagePage.jsx.

CSS forcing absolute positioning / transform overrides

Check for any global CSS that forces position: absolute; top:0; left:0 for node wrappers. Your node CSS looks fine, but other styles (not in these files) could collide. See LineagePage.css & LineageImpact.css.

C — Practical fixes (ready-to-paste code)
1) Wait for container to be measured before computing layout

Add a containerRef and a ResizeObserver to ensure the canvas is measured before calling layout.

At top of your LineagePageContent add:

import { useRef } from 'react';

const containerRef = useRef(null);
const [containerReady, setContainerReady] = useState(false);

useEffect(() => {
  if (!containerRef.current) return;
  const el = containerRef.current;
  if (el.clientWidth > 20 && el.clientHeight > 20) setContainerReady(true);
  const ro = new ResizeObserver(() => {
    if (el.clientWidth > 20 && el.clientHeight > 20) {
      setContainerReady(true);
      ro.disconnect();
    }
  });
  ro.observe(el);
  return () => ro.disconnect();
}, []);


Use the ref on your canvas wrapper:

<div className="lineage-canvas" ref={containerRef}>
  <ReactFlow ...>...</ReactFlow>
</div>


Then only call loadGraph() or getLayoutedElements() after containerReady === true. If user clicks Build Graph before the layout is ready, you can queue it.

2) Measure node size dynamically (preferable) or align dagre sizes to CSS

If you can keep nodes a fixed size use matching values. Otherwise, measure DOM node size after rendering (or set node.data.__width/__height from server if known).

Simple fix (match CSS):
Change in getLayoutedElements:

const nodeWidth = 220;  // match actual CSS (between 150 and 250)

(Replace previous 280/120). If your node content can be taller, increase nodeHeight accordingly.

Better: measure DOM after nodes are rendered (requires two-phase render):

Create nodes with temporary positions, render them invisibly, measure .react-flow__node widths/heights, then run dagre with measured dimensions. (Longer, but robust).

3) Guard againt empty edges (fallback grid layout)

If backend returns no edges, use a fallback layout so nodes don’t stack:

if (!edges || edges.length === 0) {
  // simple grid layout (n columns)
  const cols = 4;
  const spacingX = 260;
  const spacingY = 120;
  const layoutedNodes = nodes.map((n, i) => ({
    ...n,
    position: { x: (i % cols) * spacingX, y: Math.floor(i/cols) * spacingY },
    targetPosition: 'left',
    sourcePosition: 'right'
  }));
  return { nodes: layoutedNodes, edges };
}


Place that at top of getLayoutedElements().

4) Ensure dagre graph receives correct edges and node ids

Add defensive logs right before dagre layout:

console.log('Applying dagre layout to nodes:', nodes.length, 'edges:', edges.length);
const missing = nodes.filter(n => !n.id).map(n => n);
if (missing.length) console.warn('Nodes with missing id:', missing);


If you discover numeric ids, coerce them to strings:

const flowNodes = response.nodes.map(node => ({ id: String(node.id), ... }));

5) Use React Flow’s onInit to get the instance (safer than useReactFlow at top)

Replace const reactFlowInstance = useReactFlow(); with:

const [rfInstance, setRfInstance] = useState(null);
const onInit = useCallback((instance) => setRfInstance(instance), []);

...
<ReactFlow
  onInit={onInit}
  ...
>


Then call rfInstance && rfInstance.fitView(...) (safer).

6) Re-run layout on container resize / data change

Add a useEffect watching [nodesData, edgesData, containerReady] and debounce a call to computeAndApplyLayout() so layout is always recomputed when nodes/edges or canvas size change.

useEffect(() => {
