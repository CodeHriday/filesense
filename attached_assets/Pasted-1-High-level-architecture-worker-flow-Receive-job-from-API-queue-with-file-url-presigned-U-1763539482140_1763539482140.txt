1 — High-level architecture (worker flow)

Receive job (from API / queue) with file_url (presigned URL or local path) and optional password_token (ephemeral token pointing to secrets manager).

Pre-processing

Validate request, check idempotency (ingest_id or checksum).

Enforce quotas / file size limits.

Virus scan (ClamAV) before any extraction/processing.

Archive detection

Inspect magic bytes / file extension: zip, 7z, tar, gz, bz2, rar (if supported).

For ZIP: detect if password protected and which encryption (ZipCrypto vs AES).

Password handling

If encrypted: attempt to retrieve password securely via provided ephemeral password_token (look up from Vault/Secrets Manager). Never log the password.

If missing or invalid: move job to DLQ and notify owner with instructions.

Streamed extraction

Extract entries one-by-one in streaming mode (do not buffer entire archive to memory).

For each entry yield a child_file object with provenance: parent archive id, path inside archive, checksum, size, file type guessed.

File-type detection

Use python-magic / libmagic and content sniffing to determine underlying type (SAS, Avro, CSV, Parquet, JSON, XLSX, DAT, unknown).

Dispatch to handler

Call the appropriate handler (SAS handler → pyreadstat, Avro → fastavro, CSV / XLSX → streaming parsers, DAT heuristics).

For very large files, convert to Parquet (pyarrow) and write to object storage.

Provenance & metadata

Record metadata into DB: original archive meta, child file metadata, checksums (sha256), schema hints, row counts, processing steps, worker id, timestamps.

Post-processing

Apply governance steps: schema validation, PII detection, PII tag propagation, column tagging, quality checks.

Finalization

Emit success event, update file_metadata and audit logs.

DLQ / Human-in-loop

If any step fails (bad password, parse error, virus found), place job in DLQ with remediation instructions and attach metadata for debugging (error code, small sample, stacktrace sanitized).
