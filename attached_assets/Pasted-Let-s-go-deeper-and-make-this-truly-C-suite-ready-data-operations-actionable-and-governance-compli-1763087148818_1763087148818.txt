💡 2. Visualization Strategy & Color Semantics

Use a consistent visual grammar:

Color mapping (universal):

✅ Green (Success / Healthy) — 80–100% thresholds

🟦 Blue (Operational / Neutral) — ongoing volume or throughput

🟧 Yellow (Degraded / Warning) — 60–79%

🟥 Red (Critical / Failed) — <60% or open SEV1 issues

Background palette: neutral whites / grays to let data colors stand out

Typography: Inter / Open Sans, weight 500–700 for KPIs, 300–400 for labels

🔷 Recommended Chart Types
Metric	Chart Type	Notes
Data Health Index	Radial progress ring + 7-day sparkline	Center number (e.g., 90%) + small up/down arrow; use green-yellow-red color fill
File Throughput (Last 30 days)	Stacked area chart	Area 1: “Valid files”; Area 2: “Rejected/Failed” (contrast colors)
ETL Job Success Rate	Donut chart	Completed vs Failed; color-coded with tooltip on last 10 jobs
Active Critical Alerts	Counter + severity icons	Red badge, list top 3 alerts below metric
High-Risk PII Exposure	Horizontal bar	File count per classification (PII, PHI, Confidential)
Vendor SLA Compliance	Heatmap (matrix)	Vendors (Y-axis) vs SLA metrics (X-axis) with color intensity for % compliance
Governance Tag Coverage	Donut + segmented ring	“Tagged” vs “Untagged”; click to drill down to tag audit
Programmatic API Usage	Grouped bar chart	Compare API uploads vs manual uploads over time

⚙️ 4. Data Model → Metric Computations

You already have the tables; just define view-level aggregates for each metric:

Metric	SQL / Aggregation Idea
Data Health Index	weighted avg of (completeness + consistency + accuracy + validity + timeliness) from file_quality_metrics
File Throughput	COUNT(files WHERE upload_date >= now()-7d); trend = diff vs previous 7d
Job Success Rate	completed_jobs / total_jobs from transformation_jobs
Active Critical Alerts	COUNT(alert_events WHERE severity='SEV1' AND status='OPEN')
PII Exposure	COUNT(files WHERE risk_level='High' AND pii_flag=true)
Vendor Compliance	join vendor_agreements with SLA metrics table
Governance Tag Coverage	files_with_tags / total_files
API Usage	COUNT(api_calls) from api_tokens + volume grouping by token_id

These can be exposed through a single /api/dashboard/metrics endpoint returning all KPIs + chart data.
