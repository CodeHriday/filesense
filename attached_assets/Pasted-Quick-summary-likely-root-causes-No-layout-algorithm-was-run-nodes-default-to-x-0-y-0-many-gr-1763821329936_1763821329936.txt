Quick summary — likely root causes

No layout algorithm was run (nodes default to x:0,y:0) — many graph renderers place nodes at 0,0 until you compute positions.

Layout ran before container measurements (container width/height = 0 or hidden) so computed positions are invalid (all nodes end up at same point).

Nodes locked / fixed positions (fx/fy or position: 'absolute' set) so layout cannot reposition them.

Missing/incorrect edges — auto-layout needs edges to compute topology; without edges layout may stack nodes.

All nodes share the same z-index/CSS transform or parent positioning (CSS overrides, e.g., position:absolute; top:0; left:0).

IDs duplication or incorrect node IDs — the layout update fails silently and nodes collapse.

The layout function isn’t re-applied when data changes — new nodes are inserted at default coordinate (0,0).

How to confirm which problem you have (quick checks)

Inspect first node object in console — does it have position: { x: 0, y: 0 }? If yes, layout not applied.

Inspect edges list — is it empty or missing expected edges?

Ensure container has non-zero size before calling layout: document.querySelector('#canvas').clientWidth.

Check CSS on node elements for position/top/left rules that force them to the same place.

Verify each node id is unique.

Fixes (apply in this order)
1) Ensure container has size & is visible before layout

If your canvas is inside a tab or collapsed panel, layout can run while size is zero.

// Example: wait until container is measured
function whenContainerReady(selector, cb) {
  const el = document.querySelector(selector);
  if (el && el.clientWidth > 10 && el.clientHeight > 10) return cb();
  const ro = new ResizeObserver(() => {
    if (el.clientWidth > 10 && el.clientHeight > 10) {
      ro.disconnect();
      cb();
    }
  });
  ro.observe(el);
}
whenContainerReady('#lineage-canvas', () => computeAndApplyLayout(nodes, edges));

2) Run a deterministic layout algorithm (Dagre for DAGs) and set node positions

If you use React Flow / Cytoscape / Vis, compute node positions with Dagre and then set nodes with those positions.

// dagre layout (example)
import dagre from 'dagre';

const dagreGraph = new dagre.graphlib.Graph();
dagreGraph.setDefaultEdgeLabel(() => ({}));
const nodeWidth = 220;
const nodeHeight = 60;
dagreGraph.setGraph({ rankdir: 'LR', ranksep: 40, nodesep: 20 });

nodes.forEach(n => dagreGraph.setNode(n.id, { width: nodeWidth, height: nodeHeight }));
edges.forEach(e => dagreGraph.setEdge(e.source, e.target));

dagre.layout(dagreGraph);

const positioned = nodes.map(n => {
  const { x, y } = dagreGraph.node(n.id);
  return {
    ...n,
    position: { x: x - nodeWidth / 2, y: y - nodeHeight / 2 },
    // mark as positioned so renderer won't override
    targetPosition: 'left',
    sourcePosition: 'right',
  };
});
setNodes(positioned);


Key points:

Use node width/height that match your rendered node size (important).

Subtract half width/height so layout centers nodes correctly.

Use rankdir: 'LR' for left→right or 'TB' for top→bottom.

3) Confirm edges exist & are correct

If edges are missing the layout will not distribute nodes logically.

if (!edges || edges.length === 0) {
  console.warn('No edges found — layout will likely stack nodes.');
}

4) Make sure nodes are not fixed / locked

Remove fx/fy or any position: absolute forcing coordinates:

// ensure nodes are "free" for layout
nodes = nodes.map(n => ({ ...n, position: undefined, fx: undefined, fy: undefined }));

5) Re-run layout after data changes or UI resize

Debounce layout runs and reapply whenever nodes/edges change or the canvas resizes.

useEffect(() => {
  const id = setTimeout(() => computeAndApplyLayout(nodes, edges), 50); // slight delay to let DOM settle
  return () => clearTimeout(id);
}, [nodesData, edgesData, containerWidth]);

6) Check for CSS that forces stacking

Look for global CSS like:

.node { position: absolute; left: 0; top: 0; }


If found, remove or override to let the graph engine control position.

Example ReactFlow end-to-end pattern

If you use React Flow, this is the typical flow:

measure container (width/height)

compute layout (dagre)

set nodes with computed position

call fitView() if desired

// in your component
useEffect(() => {
  if (!containerRef.current) return;
  if (!nodes.length) return;
  computeDagreLayout(nodes, edges, 'LR');
  reactFlowInstance.fitView();

Other practical tips & gotchas

Node dimensions: If nodes render variable height/width (e.g., title wraps), either measure real DOM node sizes before layout or use conservative fixed sizes in layout.

Nested nodes / groups: Grouped nodes can confuse layout; flatten graph or use compound node-aware layout.

Large graphs: For thousands of nodes, compute positions server-side or in a WebWorker and progressively render subgraph.

Zoom / transforms: If you manually set CSS transforms on the canvas, ensure the layout engine is aware or applied positions account for transforms.

Duplication bug: Duplicate node IDs cause the layout to reference the same node — double-check uniqueness.

Checklist for you (copy-paste)

 Are edges present for the nodes you expect? (edges.length > 0)

 Is the canvas visible and measured (non-zero width/height) when you call layout?

 Do your nodes have unique IDs?

 Are you running a layout algorithm (dagre, cola, ELK, or Cytoscape layout)?

 Are node widths/heights provided to the layout algorithm?

 Are you overriding node CSS/positioning accidentally?
