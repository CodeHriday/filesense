Objective (one-sentence)

Ship a dedicated Lineage page under Data Governance that visualizes end-to-end lineage from vendor contract → source files → transforms → derived columns → targets; every node is clickable to reveal full metadata and derivation expressions; supports expand/collapse, filtering, time-windowed incident overlay, and performant rendering for very large graphs.

High-level approach

Build a separate micro-frontend/page under Data Governance (no changes to existing File Lineage).

Implement a Lineage Graph Service that returns precomputed graph fragments (subgraphs) on demand.

Use a modern graph renderer (React + Dagre/ELK + Cytoscape/Visx/ReactFlow) for interactive layout.

Persist lineage metadata in a normalized graph store (Postgres + PGGraph extension or a graph DB like Neo4j) and a caching layer (Redis).

Provide click-to-expand semantics that fetch node metadata and derivation expressions lazily.

Implement provenance, auditing, RBAC, and DLQ/reprocess flows for missing/incorrect lineage.

UX / Interaction Design
Page placement

New menu: Data Governance → Lineage (separate item)

Breadcrumbs: Data Governance / Lineage

Primary controls (top bar)

Environment selector (prod/stage), date/time window (incident overlay), vendor agreement selector, direction toggle (Upstream / Downstream), depth selector (1–5), type filters (tables, files, views, jobs), search (global node search), show/hide derived-columns toggle, incident overlay toggle (last X days).

Canvas & Layout

Large central canvas (pan + zoom) with:

Nodes = entities (Vendor Contract, Source File, Table, View, Job/Task, Derived Column)

Edges = data flow (arrow direction)

Node types visually distinct: vendor (shield icon), file (file icon), table (table icon), job (gear), derived column (tag + formula badge)

Color semantics: vendor agreements (indigo), sources (blue), transforms (orange), targets (green), alerts (red overlay)

Left sidebar: Search + filters + small mini-map

Right drawer: Node panel (hidden until node click) with full metadata and actions

Bottom bar: timeline scrubber for time-based incident overlay; export (PNG/SVG/JSON)

Node interactions

Hover: tooltip with short summary (name/type, last updated, row count)

Click: open right drawer with:

Full metadata (IDs, checksums, storage path, vendor agreement link if present)

Column list (for tables/files) with badges showing derived columns

For derived columns: show expression, upstream columns used, version of mapping, and preview sample

Actions: Open in Catalog, Start reprocessing, Add comment, Create monitor, Download sample

Expand node: dynamically load its immediate neighbors (depth controlled by top bar)

Derived columns highlighting: toggle to only highlight/grey-out others; show derivation expression inline and link to mapping rule

Additional features

Click on an edge to view transformation step metadata (transformation ID, script, mapping version)

Incident overlay: shade nodes/edges with incidents in last X days; click to see incident details

Diff mode: compare lineage between two timestamps (show additions/removals)

Export: selected subgraph as JSON (for audits) and SVG/PNG for sharing

Keyboard shortcuts: zoom in/out, pan, expand all neighbors, collapse

Graph data model (conceptual)

Entities (nodes):

VendorAgreement {id, name, vendor_id, effective_from, effective_to, tags, governance_rules}

SourceFile {id, name, storage_path, checksum, size_bytes, content_type, uploaded_ts, vendor_agreement_id?}

Table {id, name, schema, row_count, last_updated, db_platform}

View {id, name, query, last_updated}

Job {id, name, type, schedule, last_run_status}

Column {id, name, type, label, is_derived(bool), derivation_expression?, mapping_id?}

Mapping {id, name, expression, created_by, version, created_ts}

Incident {id, severity, summary, timestamp, node_id}

UserComments, AuditEvent

Edges:

SOURCE_OF (SourceFile → Table)

TRANSFORMED_BY (Table/File → Job)

OUTPUT_OF (Job → Table/View/File)

DERIVES_FROM (Column → Column) — multi-edge showing derivation lineage

AGREEMENT_FOR (VendorAgreement → SourceFile/Table)

ALERTED_BY (Node → Incident)

Store relationships with direction, metadata on edge (transformation id, timestamp, columns involved).
